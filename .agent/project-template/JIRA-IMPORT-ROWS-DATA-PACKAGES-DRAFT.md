## Boundary

These rows are project-control artifacts. They are not Business Central import files, do not authorize setup writes, and do not create Jira issues by themselves.

Use them to prepare a CSV/Jira import after the team confirms Jira field names and project keys.

## Proposed Jira columns

| Column | Meaning |
| --- | --- |
| Issue key candidate | Stable local key before Jira import assigns the real key. |
| Issue type | Use standard Jira-like types: Data Request, Decision, Task. |
| Summary | Short Jira summary. |
| Workstream | Project workstream. |
| Epic | Target epic or area. |
| Source package | Simulated Universaarl data package that created the need. |
| Customer owner | Fictional customer-side owner for the case study. |
| Internal owner | Consultant/architect/project owner. |
| Priority | Project priority for the implementation sequence. |
| Status | Draft project status, not Jira workflow truth. |
| Blocks BC setup | Whether this item must be resolved before a Business Central write. |
| Depends on | Upstream tickets or decisions. |
| Labels | Suggested Jira labels. |
| Acceptance criteria | Minimum completion rule. |
| UAT impact | What UAT this unlocks or protects. |
| Training impact | What training or handbook section this supports. |
| Playwright evidence need | Read-first or later execute evidence need. |
| Next action | Immediate project action. |
